## 二、文档与实现不一致（3 条，**已按"删痕迹"处理**）

### 1. `worker_helpers._bump_parent_score`：说好要写说明，从来没写（**已按"删痕迹"处理**）

```python
def _bump_parent_score(conn, parent_id, child_score, child_reasoning) -> bool:
    """
    If the child's score is more extreme than the parent's, update the
    parent's sentiment_score **and prepend a note to the reasoning field**.
    """
    ...
    if abs(child_score) > abs(parent_score) and (child_score * parent_score >= 0):
        conn.execute(
            "UPDATE ai_decisions SET sentiment_score = ? WHERE id = ?",
            (round(child_score, 4), parent_id),
        )
        return True
```

docstring 承诺了两件事，实现只做了一件。`child_reasoning` 在整个函数体里出现 0 次
（AST 计数确认），`reasoning` 字段没有任何 UPDATE。

影响：子决策把父决策的分数往极端方向拽时，父决策的 `reasoning` 里看不到"为什么被改分"。

**为什么没补实现，而是删掉参数**：补实现要往 `reasoning` 里塞前缀，但 `reasoning` 会被
判官拼进 `full_reasoning`、被前端截前 300 字展示（`routers/actionable.py` 的 `why` 字段），
塞前缀会把正文挤出去。要记"为什么改分"，正确做法是新增专门字段，而不是复用摘要文本。
既没有调用方依赖这个参数，就删掉它，并把 docstring 改成如实描述——不留一个永远不用的
入参让人误以为功能存在。

如果确实需要"改分留痕"，正确形态是：`ai_decisions` 加一列（如 `score_bump_note`），
在 `_bump_parent_score` 里写；前端按字段展示。这属于新增功能，需要你点头再做。

### 3. `_rescue_target_asset_from_content`：分类偏好传了但没生效（**已删参数**）

`ai_worker.py` 与 `worker_helpers.py` 各有一份同名实现，参数 `preferred_categories`

顺带记一个结构问题：两份同名实现本身就该合并成一份，属于后续拆分任务。
